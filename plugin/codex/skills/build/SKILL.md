---
name: build
description: Run the Studio Zero build workflow with native Codex workers when the owner explicitly requests an unattended build.
---
Read the start questions in the sz:work skill. Ask the owner in the current conversation and keep their answers verbatim. Use asked="away" only when they explicitly ask you to proceed without questions or the run is already unattended. Only the owner may select design="go". With the start questions, ask once whether a red team review is added: "레드팀 검토를 붙일까요?" (안 함 / 계획만 / 마감만 / 둘 다); pass their choice as redteam ("plan", "close" or "both"), and leave it out for 안 함.

Run the executable bin/sz-codex-build relative to this plugin's root (three directories up from this skill's directory), with the target project as the working directory. Pass one JSON object on stdin with request, asked and answers. Use a quoted heredoc or a file so the user's words stay data. The runner also accepts redteam, redteamModel (a Codex model ID for the review), facts, maxMilestones, side, and an optional Codex model ID. A redteam word it does not know stops the run before it starts, and its first stage message says which options it took. It starts fresh Codex workers and can take as long as the build. Monitor its stage messages, and do nothing else in the project while it runs: no edits, no commits, no records (sz-eyes takes the records of its contracts only from its own workers). If it ends with an error, run it again from the project with the same JSON: it resumes from .sz, keeping contracts, verdicts and commits. Never carry a build on by hand or with agents you spawn: they carry your conversation, so their verdicts are not independent, and sz-eyes refuses them until the runner runs again. On a design stop show the prototype, record the owner's actual verdict with sz-eyes contract judged design feel --verdict yes|no --said "<their words>", and restart with those words. Report stopped, notBuilt, and each evidence page from the result.

The Korean you write (to the owner, in files, on a product's screens) is the plain Korean a product team uses at work. Do not write 서다/세우다 (계획이 선다, 기준을 세운다), 짓다 (제품을 짓는다), 열리다 (결과가 열린다, 화면이 열린다) or 판 (첫 판, 새 판). Write 만들다, 구현하다, 정하다, 완성되다, 나오다, 뜨다, 보이다, 버전. The owner's own words are quoted as they said them.
