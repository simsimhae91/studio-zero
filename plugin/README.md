# sz: Claude Code 위의 Studio Zero

만들고, 만든 것을 만들지 않은 쪽이 돌아가는 제품에서 증명하고, 한 장으로 보여 준다. 그리고 그 뒤: 증명한 것을 지키면서 고치고, 주인의 말을 받아 키운다.

## 켜기

```
claude --plugin-dir /Users/hosoo/project/conclave/plugin
```

프로젝트 폴더에서 연다. 계속 쓰려면 Claude Code 안에서 `/plugin marketplace add /Users/hosoo/project/conclave` 뒤 `/plugin install sz`.

## 말하는 법

두 가지를 나눈다.

- **시킨 일을 하는 방식은 말에서 그냥 이어진다.** "고쳐 줘", "이 기능 넣어 줘"라고 하면 크기를 재고, 약속을 적고, 만들지 않은 쪽이 증명한다. 외울 것이 없다(지도가 없는 프로젝트면 먼저 지도를 쓴다).
- **따로 시작되는 단계는 부를 때만 시작한다.** 에이전트 여럿이 몇 분에서 몇 시간을 쓰는 일이라서, 지나가는 말에서 짐작으로 시작하지 않는다. 비슷한 말을 하면 시작하지 않고 어느 명령이 그 일을 하는지 한 줄로 알려 준다.

### 명령

`/` 메뉴에 `sz:`로 뜨는 것은 이 여덟 개다. 명령 뒤에 하고 싶은 말을 붙여 쓴다.

| 명령 | 언제 | 걸리는 것 |
|---|---|---|
| `/sz:build <만들 것>` | 새 제품, 또는 기능 여러 개를 끝까지 | 워크플로. 시작 전에 세션이 사장님만 답할 수 있는 것을 선택지로 최대 세 가지 묻고, 계획이 서면 예상 시간을 말한다. 에이전트 여럿, 한 시간 안팎부터. "나란히 지어 줘"라고 하면 서로 기대지 않는 마일스톤은 각자 폴더에서 동시에 짓고, 합친 뒤 선 약속 전부를 다시 보인다(아직 실제로 재 보지 않아 기본은 한 줄). 짓기는 강도 high, 계획과 검증은 세션 강도 그대로 |
| `/sz:work <요청>` | 고치기, 기능 하나 (말로만 해도 같다) | 작은 수정은 몇 분, 기능 하나는 5~10분 |
| `/sz:feedback` | 제품을 둘러보며 말하기, 보고 느낀 것 말하기 | 창이 뜬다 |
| `/sz:trial` | 사용자 대역이 끝까지 써 보기 | 대역 3명, 5분 안팎부터 |
| `/sz:worth` | 지을 만한가, 돈 낼 만한가, 얼마나 깊은가 | 웹 조사와 반박, 20~45분 |
| `/sz:ship` | 출하 | 계정·돈·첫 공개는 먼저 묻는다 |
| `/sz:tend` | 제품 점검, 다음에 할 것 | 10분 안팎부터 |
| `/sz:onboard` | 하던 프로젝트 파악 (지도 쓰기) | 몇 분, 코드는 안 건드린다 |

나머지(`backend`, `taste`, `verify`, `game`)는 일하는 쪽이 스스로 읽는 지식이라 메뉴에 없다.

| 하고 싶은 것 | 이렇게 말한다 | 일어나는 일 |
|---|---|---|
| 지을 만한지 묻는다 (부를 때만) | `/sz:worth`, "이거 돈 될까", "출시할 만한가", "뭘 만들까" | 요청할 때만 실행하고, 만들기 전에 거치는 단계가 아니다. 서비스의 근거를 같은 줄로 묻는다: 누가, 지금 무엇으로, 이미 돈이 오가는가, 어디서 실망하나, 갈아탄 적이 있나, 어디서 만나나. 세상에 대한 줄은 누구나 열 수 있는 페이지의 문장으로만 보였다고 하고, 그 문장이 그 페이지에 있는지 다시 열어 확인한다. 쓰지 않은 에이전트가 인용을 하나씩 읽고 근거를 뒤집어 본다. 깊이는 사람들이 대신 쓰는 것들과의 대조표로 낸다(있음·얕음·없음·안 함). 기본값은 "짓지 않는다"이고, 팔리는지는 진짜 사람에게 가장 싸게 묻는 법과 미리 적은 기준으로 남긴다 |
| 하던 프로젝트를 맡긴다 | "이 프로젝트 파악해 줘" | 지도(`.sz/map.md`)를 쓴다. 코드는 안 건드린다 |
| 작은 수정 | "닉네임 길면 잘리는 거 고쳐 줘" | 바로 고치고 전후 사진을 보여 준다 |
| 기능 하나 | "지출 고치기 기능 넣어 줘" | 끝나면 참인 것을 먼저 적고, 만들고, 다른 에이전트가 제품에서 증명하고, 증거 한 장 |
| 새 제품, 큰 기능 묶음 | "모임 정산 서비스 만들어 줘. 워크플로로 끝까지" | 묻고(다섯 개까지), 명세, 마일스톤마다 계약·구현·검증·증거. 이미 명세가 있으면 이어서 넓힌다 |
| 보고 느낀 것을 말한다 | "숫자가 좀 작은 느낌", 스크린샷 붙이고 한마디 | 이해한 것과 의견을 한 번에 말하고, 작은 건 바로 해서 전후를 보여 주고, 큰 것만 묻는다 |
| 돈 낼 만한지 본다 (부를 때만) | `/sz:trial`, "유저 입장에서 끝까지 써 봐" | 코드를 안 본 대역이 이 제품의 사람들이 되어 처음부터 끝까지, 다음 날과 일주일 뒤까지 써 본다. 사람과 결제 사이에 있는 것을 먼저 할 순서로, 화면과 함께 내놓는다. 결제 창구는 그다음 |
| 제품을 둘러보며 말한다 | "둘러보고 피드백 줄게" | 창이 하나 뜬다. 평소처럼 쓰다가 **말하기**를 누르고, 말하려는 곳을 누르고, 적는다. **끝내기**를 누르면 처리한다 |
| 게임을 만든다 | "벽돌 깨기 만들어 줘" | 게임이 자기 상태를 말하게 짓고, 시간을 멈춰 놓고 규칙을 증명한다("3초 뒤 점수가 3이다"). 재미와 손맛은 주인이 본다 |
| 세상에 내놓는다 (부를 때만) | `/sz:ship`, "출하해 줘", "배포해 줘" | 내보낼 버전을 내보낼 모양 그대로 띄워 놓고(후보) 관문의 앞 절반을 증명하고, 내보내고, 사람들이 닿는 주소에서 뒤 절반을 증명한다. 깨졌으면 되돌리고 말한다. 계정·돈·첫 공개는 먼저 묻는다 |
| 제품을 돌본다 (부를 때만) | `/sz:tend`, "돌봐 줘", "점검해 줘" | 전에 증명한 것이 아직 참인지, 실패, 사용, 처음 1분, 의존성을 보고 깨진 건 고치고 나머지는 순위와 근거로 내놓는다 |

## 눈이 보는 것

| 대상 | 명령 | 비고 |
|---|---|---|
| 웹 | `sz-eyes web look\|do` | 헤드리스 Chrome, 주인의 브라우저와 무관 |
| 웹 게임, 스스로 움직이는 화면 | `sz-eyes web do --clock` | 시간을 세워 두고 규칙을 증명 |
| Electron 데스크톱 앱 | `sz-eyes electron look\|do` | 앱 데이터는 따로 만든 폴더에(주인의 실제 데이터를 열 앱은 띄우기 전에 거절), 창은 주인 화면에 안 보이고, 주인이 띄워 둔 같은 앱은 그대로 |
| iOS | `sz-eyes ios ...` | 눈 전용 시뮬레이터 |
| 아직 못 보는 것 | 브라우저 확장, 패키징된 .app, Android, Windows | 프로젝트 자체 검사로 확인하고 "확인 못 함"으로 말한다 |

## 여러 제품을 한 장으로

```
sz-eyes overview <제품들이 든 폴더> --out <파일.html>
```

맨 위에 깨진 약속과 **주인의 판단을 기다리는 것**(무엇을 봐 달라는지, 그것을 보여 주는 증거 페이지), 그 아래 제품마다 어디에 무엇이 살아 있는지, 마지막으로 점검한 때, 남은 일, 최근에 한 일. 읽기만 하고 아무것도 바꾸지 않는다. "전체 어떻게 돼 가?"라고 말해도 된다.

## 내놓을 때 지나는 관문

모든 제품의 모든 출하가 같은 줄을 지난다. 줄마다 보이거나, 까닭을 달아 면제한다(증거 페이지에 적힌다). 조용히 빠지는 줄은 없다.

| 내보내기 전, 후보에서 | 내보낸 뒤, 사람들이 닿는 주소에서 |
|---|---|
| 전에 증명한 약속이 그대로 참이다 | 답하는 것이 이 버전이다 |
| 브라우저가 받는 것 안에 서버의 비밀이 없다 | 제품의 한 가지 일이 끝까지 된다 |
| 남이 넣은 것은 보이지 않는다 | 비밀이 내려오지 않는다 |
| 살아 있는 데이터의 사본으로 새 버전이 뜬다 | 새 오류가 기록되지 않았다 |
| 저장 모양의 변경이 넣어 둔 것을 잃지 않는다 | |
| 사본을 뜰 수 있고 되살아난다 | 넣어 둔 것이 그대로다 |
| 되돌리는 길이 적혀 있고 해 봤다 | |

지우기·이름 바꾸기·형 바꾸기처럼 넣어 둔 것을 잃거나 앞 버전을 깨는 변경은 주인이 그 변경에 "예"라고 한 말이 출하 기록에 적혀야만 나간다.

**키는 금고에.** 호스팅 토큰이나 로그인 비밀 값은 대화에 붙여 넣지 않는다. 복사한 뒤 `! pbpaste | sz-eyes secret set host/cloudflare/api-token`처럼 주인이 직접 금고(macOS 키체인, 스튜디오가 쓰던 그 금고)에 넣는다. 하네스는 이름으로만 쓴다: 키가 필요한 명령을 그 키를 환경에 넣어 돌리고, 명령이 키를 찍어도 세션에는 가려져서 온다.

`sz-eyes release list`가 어디에 무엇을 내보냈는지, 지금 무엇이 답해야 하는지, 되돌리는 명령이 무엇인지 말한다.

## 프로젝트에 생기는 것 (`.sz/`)

| 파일 | 무엇 | 누가 고치나 |
|---|---|---|
| `map.md` | 띄우는 법, 보는 법, 있는 검사, 배포와 데이터, 규칙 | 하네스. 틀리면 말해 주면 된다 |
| `spec.md` | 제품이 무엇이고 무엇을 어떤 순서로 만드는지 | 하네스(큰 작업 때) |
| `owner.md` | 주인이 원한다고 말한 것. 다음 빌드가 먼저 읽는다 | 하네스가 피드백에서 적는다. **직접 고쳐도 된다** |
| `backlog.md` | 알고 있고 아직 안 한 것 | 하네스가 더한다. **직접 줄을 더하고 지워도 된다** |
| `contracts/` | 작업마다 끝나면 참인 것과 판정 | 손으로 고치지 않는다 |
| `standing.json` | 전에 증명한 것이 마지막으로 참이었던 때 | 손으로 고치지 않는다 |
| `evidence/` | 증거 페이지(`report.html`)와 사진 | |
| `feedback/` | 주인이 말한 것과 그 뒤(`report.html`) | |
| `trials/` | 대신 써 본 기록: 누가, 걸음마다 무엇을 원했고 화면이 무엇을 줬는지, 낼 것인지(`report.html`) | |
| `worth/` | 서비스의 근거: 후보마다 줄과 인용, 대신 쓰는 것, 깊이 대조표, 반박과 답, 진짜 사람에게 물을 것 (`index.html`, `<id>/page.html`) | |
| `progress.md` | 날짜별로 한 일 한 줄씩 | |

## 지켜지는 것

- 얼린 검사는 만드는 쪽이 못 고친다. 닫은 뒤에도, 그 주장이 서 있는 동안은.
- 전에 증명한 것은 다음 작업 뒤에 다시 보인다. 깨뜨렸으면 그 작업은 닫히지 않는다.
- 약속을 바꾸는 것은 된다. 무엇을 왜 바꾸는지가 증거 페이지에 적힌다.
- 주인의 시뮬레이터, 브라우저 프로필, 개발 서버 포트, 작업 중인 폴더는 실험에 쓰지 않는다.
- 살아 있는 것을 지우지 않는다. 호스팅된 DB를 초기화하거나 프로젝트·앱·볼륨을 지우는 명령은 훅이 거절한다. 살아 있는 것을 바꾸는 길은 새 버전을 내보내는 것이고, 되돌리는 길은 지도에 적힌 명령이다. 정말 지워야 하면 주인이 직접 돌린다(`! <명령>`).
- 이 Mac에서 도는 주인의 다른 일을 끄지 않는다. 하네스가 띄우는 서버는 포트를 기계에서 받고(`sz-eyes port`), 자기가 띄운 것만 그 프로세스 번호로 끈다. "그 포트를 잡고 있는 것", "그 이름의 프로세스 전부", "모든 컨테이너·시뮬레이터"를 끄는 명령은 훅이 거절한다. 주인이 정말 그 명령을 원하면 직접 돌린다(`! <명령>`).
