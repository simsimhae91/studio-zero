# sz: Claude Code 위의 Studio Zero

만들고, 만든 것을 만들지 않은 쪽이 돌아가는 제품에서 증명하고, 한 장으로 보여 준다. 그리고 그 뒤: 증명한 것을 지키면서 고치고, 주인의 말을 받아 키운다.

## 켜기

```
claude --plugin-dir /Users/hosoo/project/conclave/plugin
```

프로젝트 폴더에서 연다. 계속 쓰려면 Claude Code 안에서 `/plugin marketplace add /Users/hosoo/project/conclave` 뒤 `/plugin install sz`.

Codex에서 아이디어를 파려면 입력창에서 **dive (sz)**를 선택하고 첫 생각을 적는다. 선택지에는 같은 대화에서 번호나 문장으로 답한다. 훅 기록이 없어도 현재 Codex 스레드에 남은 직접 입력을 확인한다.

## Codex에서 빌드

로컬 체크아웃에서 `pnpm install`, `codex plugin marketplace add .`, `codex plugin add sz@studio-zero`를 실행한다. Codex 입력창에서 `$sz`를 입력해 **build (sz)**를 선택하고 요청을 적는다. 시작 질문에 답하면 빌드가 진행된다. 같은 실행기를 터미널에서도 부를 수 있다. 대상 프로젝트 폴더에서 실제 요청과 답을 JSON으로 전달한다.

```sh
/Users/hosoo/project/conclave/plugin/bin/sz-codex-build < request.json
```

```json
{
  "request": "정수 세 배를 출력하는 CLI를 고쳐 줘",
  "asked": "owner",
  "answers": "기존 CLI를 유지하고 양수·음수 모두 확인해 주세요.",
  "maxMilestones": 1
}
```

Mobbin을 쓰려면 `codex mcp add mobbin --url https://api.mobbin.com/mcp`로 등록하고 브라우저에서 로그인한다. Codex 디자인 작업자는 등록된 Mobbin에서 화면·사용 흐름·웹 섹션을 검색할 수 있다. 사용자가 비활성화한 도구는 제외한다.

로그에는 단계·모델·추론 강도가 나오고 최종 JSON에는 증거 페이지와 중단 사유가 나온다. 모델은 `model`에 Codex 모델 ID 하나로 지정한다. 기본은 `gpt-6.2-astra`이며 검증자는 새 대화에서 제품 소스를 읽고 실행하며 증거를 기록한다. 각 명령은 `codex sandbox` 권한 프로필로 실행한다. 동결된 검사는 빌더에게 읽기 전용이고, 계약 판정은 역할별 `sz-eyes` 명령으로 기록한다. 로컬 제품을 시험하기 위해 루프백 접근을 허용한다. 외부 패키지 다운로드나 기기 접근이 필요한 프로젝트는 의존성과 실행 환경을 먼저 준비한다. 현재 이 Mac의 Codex 샌드박스에서는 헤드리스 Chrome이 시작 중 종료되어 브라우저 화면 검증이 막힌다. CLI 제품은 실행과 증거 마감까지 확인했다. 시안을 기다리거나 외부 조건으로 멈추면 결과의 `stopped`를 읽고 기존 프로젝트에서 다시 실행한다.

실행기는 첫 작업자를 띄울 때부터 프로젝트를 잡는다. 저장소의 git 폴더에 `sz-build-run.json`(pid, 시작 시각, 작업자에게만 주는 토큰의 해시)을 남긴다. 그동안 `sz-eyes`는 계약·증거·기존 약속 기록을 그 토큰을 가진 작업자에게서만 받는다. 주인의 시안 판정(`contract judged`)과 읽기는 언제나 된다. 실행기가 오류로 멈추면 기록이 이유와 함께 남는다. 같은 JSON으로 다시 실행하면 `.sz`에서 이어 간다. 손으로 마무리하거나 직접 띄운 에이전트로 마무리하지 않는다. 그런 에이전트는 세션의 대화를 그대로 이어받아 독립 검증이 되지 않는다. 작업자가 커밋하지 않은 파일을 남기면 같은 역할의 짧은 작업자에게 한 번 돌려준다. 그래도 남으면 파일 이름을 대고 멈춘다. (2026-11-23 yt_support: 실행기가 76분째 남은 파일 하나 때문에 멈췄고, 세션이 나머지를 직접 띄운 에이전트로 마무리했다. 그 과정에서 화면 12쌍을 세 번 다시 찍었다.)

### Codex에서 Electron 창 검증

빌더와 검증자는 빌드된 Electron 앱의 첫 창과 조작을 `sz` MCP의 `electron` 도구로 확인한다. 작업자의 일반 명령과 파일 편집은 기존 역할별 샌드박스에서 실행한다. GUI를 열 때마다 이 Mac의 준비된 macOS VM을 복제한다. 게스트에는 프로젝트 스냅샷과 실행 도구를 읽기 전용으로 연결한다. 게스트의 네트워크는 외부와 단절되어 있고, 앱 데이터는 해당 실행과 함께 폐기한다. 같은 프로필로 여러 번 실행해야 하는 검사는 한 Node 흐름에 담는다.

Apple Silicon Mac에서 한 번 준비한다. 아래 경로는 이 Mac의 외장 APFS 볼륨이다.

```sh
brew install openai/tools/softnet openai/tools/tart
install -d -m 700 /Volumes/DEV-SSD/sz-tart ~/.config/sz
ln -s /Volumes/DEV-SSD/sz-tart ~/.config/sz/electron-vm
TART_HOME=/Volumes/DEV-SSD/sz-tart tart clone ghcr.io/cirruslabs/macos-tahoe-base:latest sz-electron-base
TART_HOME=/Volumes/DEV-SSD/sz-tart tart set sz-electron-base --display 1920x1200px --no-display-refit
```

호출 예시는 다음과 같다.

- 첫 창을 확인하려면 `["look", "apps/desktop", "--env", "YTS_E2E_APP_DATA={data}"]`를 전달한다. `do`는 기존 `sz-eyes electron do`의 `--step`을 사용한다.
- 프로젝트의 GUI 검사는 `["node", "apps/desktop/e2e/example.ts", "--shots", "/tmp/sz-evidence"]`처럼 실행한다. 빌드 결과와 설치한 프로젝트 의존성이 스냅샷에 포함된다. 프로젝트가 포함한 실행 파일은 도구의 선택 입력인 `env`로 게스트의 `PATH`에 추가할 수 있다. 게스트의 프로젝트 경로는 `/private/tmp/sz-input/project`다. 별도 시스템 도구를 설치할 때는 기본 VM에 준비한다.
- 각 실행은 게스트의 `/tmp/sz-evidence` 바로 아래에 쓴 PNG를 새 `.sz/evidence/<계약>/electron-…/` 폴더로 가져온다. 도구가 출력한 프로젝트 경로를 판정 근거로 사용한다.

## 말하는 법

두 가지를 나눈다.

- **시킨 일을 하는 방식은 말에서 그냥 이어진다.** "고쳐 줘", "이 기능 넣어 줘"라고 하면 크기를 재고, 약속을 적고, 만들지 않은 쪽이 증명한다. 외울 것이 없다(지도가 없는 프로젝트면 먼저 지도를 쓴다).
- **따로 시작되는 단계는 부를 때만 시작한다.** 에이전트 여럿이 몇 분에서 몇 시간을 쓰는 일이라서, 지나가는 말에서 짐작으로 시작하지 않는다. 비슷한 말을 하면 시작하지 않고 어느 명령이 그 일을 하는지 한 줄로 알려 준다.

### 명령

`/` 메뉴에 `sz:`로 뜨는 것은 이 아홉 개다. 명령 뒤에 하고 싶은 말을 붙여 쓴다.

| 명령 | 언제 | 걸리는 것 |
|---|---|---|
| `/sz:dive <한 줄 생각>` | 지도나 계획보다 먼저, 한 줄 아이디어를 머릿속이 명확해질 때까지 같이 파기 | 여러 라운드. 종류가 다른 방향 셋과 와일드카드 하나를 장면과 화면 스케치로 먼저 보이고, 고른 쪽으로 좁힌다. 의견 대신 마지막으로 그랬던 때를 묻고, 남의 앱 리뷰나 보고서는 읽어 와서 출처와 함께 보인다. 정해진 줄마다 사장님이 한 말이 그대로 붙어야 하고(세션이 쓴 문장은 사장님 말로 기록되지 않는다), 모든 줄이 정해지거나 사장님 말로 비워 둬야 닫힌다. 팔릴지는 `/sz:worth`에서 판단한다. 결과는 `idea.md` 한 장과, 지을 것을 정한 `brief.md` 한 장이다 |
| `/sz:build <만들 것>` | 새 제품, 또는 기능 여러 개를 끝까지 | 워크플로. 시작 전에 세션이 사장님만 답할 수 있는 것을 선택지로 몇 가지만 묻는다. 화면이 있는 새 제품은 먼저 모든 화면을 기획하고 눌러 볼 수 있는 시안 하나로 그려 잰 뒤 멈춘다: 사장님이 시안을 보고 한 말을 적고 다시 돌리면, 된다고 했으면 시안대로 짓고 아니라고 했으면 말한 것만 다시 그린다(보지 않고 바로 짓게 하려면 `design: "go"`). 시안과 함께, 제품의 한 가지 일이 진짜로 돌려면 사장님만 줄 수 있는 것(키, 계정)과 주는 법, 첫 판에서 아직 진짜가 아닌 것과 그 까닭을 말한다. 그 일의 길에 있는 것과 요청에 적은 것은 모두 진짜이거나 사장님이 "일단 예시로"라고 한 말이 있어야 짓기 시작한다. 새 제품은 빌더 하나가 전체를 한 번에 짓고(한 시간쯤에 볼 수 있다), 검증자 셋이 전체를 본 뒤, 서 있는 제품을 보고 깊이를 계획한다. 서로 기대지 않는 마일스톤은 각자 폴더에서 동시에 짓고 합친 뒤 선 약속 전부를 다시 보인다(`side: 1`이면 한 줄). 짓기는 강도 high, 계획과 검증은 세션 강도 그대로. 계획 전에 공표 기준을 한 번 살펴보고 해당하면 `.sz/facts.md`에 남긴다. 다음 런부터는 그 페이지가 서 있는 동안(30일, 또는 요청이 페이지에 없는 기준을 필요로 할 때까지) 발행처를 다시 읽지 않는다(`facts: "on"`이면 다시 읽고, `"off"`면 생략). `redteam`은 계획·마감 중 지정한 단계에 새 대화의 검토를 더한다(마일스톤당 5~10분). `redteamModel`에 다른 모델을 지정하면 그 모델이 검토한다 |
| `/sz:work <요청>` | 고치기, 기능 하나 (말로만 해도 같다) | 작은 수정은 몇 분, 기능 하나는 5~10분 |
| `/sz:feedback` | 제품을 둘러보며 말하기, 보고 느낀 것 말하기 | 창이 뜬다 |
| `/sz:trial` | 사용자 대역이 끝까지 써 보기 | 대역 3명, 5분 안팎부터 |
| `/sz:worth` | 지을 만한가, 돈 낼 만한가, 얼마나 깊은가 | 웹 조사와 반박, 20~45분 |
| `/sz:ship` | 출하 | 계정·돈·첫 공개는 먼저 묻는다 |
| `/sz:tend` | 제품 점검, 다음에 할 것 | 10분 안팎부터 |
| `/sz:onboard` | 하던 프로젝트 파악 (지도 쓰기) | 몇 분, 코드는 안 건드린다 |

나머지(`backend`, `taste`, `design`, `verify`, `game`)는 일하는 쪽이 스스로 읽는 지식이라 메뉴에 없다.

| 하고 싶은 것 | 이렇게 말한다 | 일어나는 일 |
|---|---|---|
| 한 줄 생각을 같이 판다 (부를 때만) | `/sz:dive 단톡방 정산이 귀찮아`, "이 아이디어 같이 파 보자", "딥다이브 해 줘" | 방향 셋과 와일드카드를 보이고 고른 쪽으로 좁히며, 줄(누가·어떤 순간, 지금은 무엇으로, 그 한 가지, 처음 1분, 다시 여는 이유, 안 하는 것, 닮고 싶은 것, 다 됐다는 기준; 앱은 마지막으로 불편했던 때와 어디에 붙나, 게임은 루프·승패·깊이·보고서 렌즈)이 사장님 말로 다 정해질 때까지 묻는다. "이런 앱 있으면 좋겠다" 같은 지나가는 말로는 시작하지 않는다 |
| 지을 만한지 묻는다 (부를 때만) | `/sz:worth`, "이거 돈 될까", "출시할 만한가", "뭘 만들까" | 요청할 때만 실행하고, 만들기 전에 거치는 단계가 아니다. 서비스의 근거를 같은 줄로 묻는다: 누가, 지금 무엇으로, 이미 돈이 오가는가, 어디서 실망하나, 갈아탄 적이 있나, 어디서 만나나. 세상에 대한 줄은 누구나 열 수 있는 페이지의 문장으로만 보였다고 하고, 그 문장이 그 페이지에 있는지 다시 열어 확인한다. 쓰지 않은 에이전트가 인용을 하나씩 읽고 근거를 뒤집어 본다. 깊이는 사람들이 대신 쓰는 것들과의 대조표로 낸다(있음·얕음·없음·안 함). 기본값은 "짓지 않는다"이고, 팔리는지는 진짜 사람에게 가장 싸게 묻는 법과 미리 적은 기준으로 남긴다 |
| 하던 프로젝트를 맡긴다 | "이 프로젝트 파악해 줘" | 지도(`.sz/map.md`)를 쓴다. 코드는 안 건드린다 |
| 작은 수정 | "닉네임 길면 잘리는 거 고쳐 줘" | 바로 고치고 전후 사진을 보여 준다 |
| 기능 하나 | "지출 고치기 기능 넣어 줘" | 끝나면 참인 것을 먼저 적고, 만들고, 다른 에이전트가 제품에서 증명하고, 증거 한 장 |
| 새 제품, 큰 기능 묶음 | "모임 정산 서비스 만들어 줘. 워크플로로 끝까지" | 묻고(다섯 개까지), 명세, 마일스톤마다 계약·구현·검증·증거. 이미 명세가 있으면 이어서 넓힌다 |
| 보고 느낀 것을 말한다 | "숫자가 좀 작은 느낌", 스크린샷 붙이고 한마디 | 이해한 것과 의견을 한 번에 말하고, 작은 건 바로 해서 전후를 보여 주고, 큰 것만 묻는다 |
| 돈 낼 만한지 본다 (부를 때만) | `/sz:trial`, "유저 입장에서 끝까지 써 봐" | 코드를 안 본 대역이 이 제품의 사람들이 되어 처음부터 끝까지, 다음 날과 일주일 뒤까지 써 본다. 사람과 결제 사이에 있는 것을 먼저 할 순서로, 화면과 함께 내놓는다. 결제 창구는 그다음 |
| 제품을 둘러보며 말한다 | "둘러보고 피드백 줄게" | 창이 하나 뜬다. 평소처럼 쓰다가 **말하기**를 누르고, 말하려는 곳을 누르고, 적는다. **끝내기**를 누르면 처리한다 |
| 게임을 만든다 | "벽돌 깨기 만들어 줘" | 게임이 자기 상태를 말하게 짓고, 시간을 멈춰 놓고 규칙을 증명한다("3초 뒤 점수가 3이다"). 재미와 손맛은 주인이 본다 |
| 세상에 내놓는다 (부를 때만) | `/sz:ship`, "출하해 줘", "배포해 줘" | 내보낼 버전을 내보낼 모양 그대로 띄워 놓고(후보) 관문의 앞 절반을 증명하고, 내보내고, 사람들이 닿는 주소에서 뒤 절반을 증명한다. 깨졌으면 되돌리고 말한다. 계정·돈·첫 공개는 먼저 묻는다 |
| 제품을 돌본다 (부를 때만) | `/sz:tend`, "돌봐 줘", "점검해 줘" | 전에 증명한 것이 아직 참인지, 실패, 사용, 처음 1분, 의존성을 보고 깨진 건 고치고 나머지는 순위와 근거로 내놓는다 |

## 눈이 보는 것

| 대상 | 명령 | 비고 |
|---|---|---|
| 웹 | `sz-eyes web look\|do` | 헤드리스 Chrome, 주인의 브라우저와 무관 |
| 웹 게임, 스스로 움직이는 화면 | `sz-eyes web do --clock` | 시간을 세워 두고 규칙을 증명 |
| Electron 데스크톱 앱 | `sz-eyes electron look\|do` | 앱 데이터는 따로 만든 폴더에(주인의 실제 데이터를 열 앱은 띄우기 전에 거절), 창은 주인 화면에 안 보이고, 주인이 띄워 둔 같은 앱은 그대로 |
| iOS | `sz-eyes ios ...` | 눈 전용 시뮬레이터 |
| 아직 못 보는 것 | 브라우저 확장, 패키징된 .app, Android, Windows | 프로젝트 자체 검사로 확인하고 "확인 못 함"으로 말한다 |

## 여러 제품을 한 장으로

```
sz-eyes overview <제품들이 든 폴더> --out <파일.html>
```

맨 위에 깨진 약속과 **주인의 판단을 기다리는 것**(무엇을 봐 달라는지, 그것을 보여 주는 증거 페이지), 그 아래 제품마다 어디에 무엇이 살아 있는지, 마지막으로 점검한 때, 남은 일, 최근에 한 일. 읽기만 하고 아무것도 바꾸지 않는다. "전체 어떻게 돼 가?"라고 말해도 된다.

## 내놓을 때 지나는 관문

모든 제품의 모든 출하가 같은 줄을 지난다. 줄마다 보이거나, 까닭을 달아 면제한다(증거 페이지에 적힌다). 조용히 빠지는 줄은 없다.

| 내보내기 전, 후보에서 | 내보낸 뒤, 사람들이 닿는 주소에서 |
|---|---|
| 전에 증명한 약속이 그대로 참이다 | 답하는 것이 이 버전이다 |
| 브라우저가 받는 것 안에 서버의 비밀이 없다 | 제품의 한 가지 일이 끝까지 된다 |
| 남이 넣은 것은 보이지 않는다 | 비밀이 내려오지 않는다 |
| 살아 있는 데이터의 사본으로 새 버전이 뜬다 | 새 오류가 기록되지 않았다 |
| 저장 모양의 변경이 넣어 둔 것을 잃지 않는다 | |
| 사본을 뜰 수 있고 되살아난다 | 넣어 둔 것이 그대로다 |
| 되돌리는 길이 적혀 있고 해 봤다 | |

지우기·이름 바꾸기·형 바꾸기처럼 넣어 둔 것을 잃거나 앞 버전을 깨는 변경은 주인이 그 변경에 "예"라고 한 말이 출하 기록에 적혀야만 나간다.

**키는 금고에.** 호스팅 토큰이나 로그인 비밀 값은 대화에 붙여 넣지 않는다. 주인이 직접 금고(macOS 키체인, 스튜디오가 쓰던 그 금고)에 넣는다: `sz-eyes secret has host/cloudflare/api-token`이 넣는 줄을 도구의 전체 경로로 내준다(`! pbpaste | <전체 경로>/sz-eyes secret set host/cloudflare/api-token`). 그 줄을 세션 입력창에 먼저 넣어 두고, 키를 복사한 다음 Enter를 누른다. 줄을 나중에 복사하면 클립보드의 키가 그 줄로 바뀐다. 하네스는 이름으로만 쓴다: 키가 필요한 명령을 그 키를 환경에 넣어 돌리고, 명령이 키를 찍어도 세션에는 가려져서 온다.

`sz-eyes release list`가 어디에 무엇을 내보냈는지, 지금 무엇이 답해야 하는지, 되돌리는 명령이 무엇인지 말한다.

## 지켜지는 것

- 얼린 검사는 만드는 쪽이 못 고친다. 닫은 뒤에도, 그 주장이 서 있는 동안은.
- 전에 증명한 것은 다음 작업 뒤에 다시 보인다. 깨뜨렸으면 그 작업은 닫히지 않는다.
- 약속을 바꾸는 것은 된다. 무엇을 왜 바꾸는지가 증거 페이지에 적힌다.
- 주인의 시뮬레이터, 브라우저 프로필, 개발 서버 포트, 작업 중인 폴더는 실험에 쓰지 않는다.
- 살아 있는 것을 지우지 않는다. 호스팅된 DB를 초기화하거나 프로젝트·앱·볼륨을 지우는 명령은 훅이 거절한다. 살아 있는 것을 바꾸는 길은 새 버전을 내보내는 것이고, 되돌리는 길은 지도에 적힌 명령이다. 정말 지워야 하면 주인이 직접 돌린다(`! <명령>`).
- 이 Mac에서 도는 주인의 다른 일을 끄지 않는다. 하네스가 띄우는 서버는 포트를 기계에서 받고(`sz-eyes port`), 자기가 띄운 것만 그 프로세스 번호로 끈다. "그 포트를 잡고 있는 것", "그 이름의 프로세스 전부", "모든 컨테이너·시뮬레이터"를 끄는 명령은 훅이 거절한다. 주인이 정말 그 명령을 원하면 직접 돌린다(`! <명령>`).
