# Fine Gear (stage 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A small edit runs in a slot (a clone of the project in its own container) beside whatever else the project is doing, is checked in proportion to what it changed, and lands on main by itself; a full check walks main with no engine.

**Architecture:** A slot is addressed by a project-shaped handle with a `slot` number, which only the sandbox layer reads: every caller that passes its project on reaches the slot unchanged. A `Slots` service takes, syncs and releases slots and moves commits to the project's repository as bundles. `product/scope.ts` turns a diff into the screens and scenarios to walk. The harness gains an edit lane (`inline_edit`, `check`); the heavy lane is left as it is.

**Tech Stack:** TypeScript on Node 24 (type stripping, no build step for the daemon), node:test, SQLite via the daemon's `Store`, Docker through OrbStack, git inside the sandbox image (2.39), playwright-core for the walk tests.

**Spec:** `docs/superpowers/specs/2026-11-15-fine-gear-design.md`

## Global Constraints

- Slots a project: 2 (`slots.perProject`). Tasks at once, all projects: 3. Idle slot container stopped after 15 minutes.
- Slot names: container `sz-<slug>-s<n>`, volume `sz-<slug>-s<n>-ws`, the project's own network; the project's volume mounted at `/main`, read-only. `n` starts at 1; 0 is the project's own sandbox.
- A slot never writes to the project's volume. Commits leave it as a bundle on stdout (base64), as `harness/SelfHosting.ts` does.
- The heavy lane (build, refactor, ideate, kirby_materialize, milestones, and every kind on the Core project) keeps its behaviour: no change to what its tests assert.
- `inline_edit` off Core is always the fast track. `apply_schema` is refused in a slot.
- Light tasks: `inline_edit` and `check` on a project other than `prj_core`.
- Scope never skips silently: refused, none (docs only), all, or some, each with its reason, emitted as gate `scope`.
- A prefix step is one that 80% or more of the scenarios carry. A source change that reaches more than 60% of the files that name a screen is `all`.
- Nothing here calls a model except the engine of an `inline_edit`. `check` spends no tokens.
- User-facing text is Korean, with no em-dashes; code comments and commits are English.
- Schema version becomes 19. Back up `~/.studio-zero/studio-zero.db` before deploying.

## Review Focus

- A daemon restart while a slot holds a task: the slot map is memory only. Expected: after restart no slot is held, and a resumed or re-queued task takes a slot again and finds its branch (it was exported when the task was parked). Test in Task 6.
- Main moves between an edit's verification and its landing (another edit landed first). Expected: rebased, verified again, landed; never a merge of what was not verified. Test in Task 3 and Task 6.
- Two edits touch the same lines. Expected: the second is sent back with the files that conflict, and with no rounds left it fails with its branch exported. Test in Task 3.
- An edit that changes `supabase/migrations`. Expected: refused at scope with the reason, not landed, nothing applied. Test in Task 4 and Task 6.
- A project with no screen plan, or one whose changed screen no scenario reaches. Expected: the walk is skipped only when there is no plan at all (smoke runs instead, as today); otherwise `all`. Test in Task 4.

### Task 3: Slots: take, sync, export, land

**Files:**
- Create: `packages/daemon/src/sandbox/Slots.ts`
- Modify: `packages/daemon/src/sandbox/scripts.ts` (`syncSlotScript`, `slotDepsScript`, `rebaseOntoMainScript`, `bundleOutScript`, `landScript`), `packages/daemon/src/app/compose.ts`
- Test: `packages/daemon/test/slots.test.ts` (new; real git through `localDocker`)

**Interfaces:**
- Consumes: Task 2's `Place`, `OrbStackManager.exec/ensure/stop`.
- Produces:
```ts
type Landing = { landed: true; commit: string } | { landed: false; why: 'nothing' } | { landed: false; why: 'conflict'; files: string[] } | { landed: false; why: 'checks' };
class Slots {
  take(project: Project, taskId: string, signal?: AbortSignal): Promise<Place>;
  release(place: Place): void;
  /** Moves `main..branch` into the project's repository under the same name. False when there is nothing on it. */
  export(place: Place, branch: string): Promise<boolean>;
  /** Under the project's landing lock. `again` is called when main had moved and the work now stands on new ground. */
  land(place: Place, branch: string, again: () => Promise<boolean>): Promise<Landing>;
  landing<T>(projectId: string, fn: () => Promise<T>): Promise<T>;
  reap(now: number): Promise<void>;
}
```
- `take` syncs: clone from `/main` when the slot has no repository; detach, fetch every head of `/main` over the slot's, `checkout -f -B main`, `clean -fdq`; then dependencies by the lockfile's hash kept in `.git/sz-deps` (`cp -a --reflink=auto /main/node_modules .` when the project's lockfile has the same hash, else the package manager the lockfile names with its frozen flag).
- `land`: fetch `/main` main; when it is not an ancestor of the branch, rebase (conflict: abort, return the files); when rebased, `await again()` and return `checks` on false; bundle `main..branch`; in the project's sandbox fetch the bundle into `refs/heads/<branch>` and move main (`merge --ff-only` when main is checked out there, else `update-ref refs/heads/main <new> <old>`). One retry when the old value no longer matches.

- [ ] Tests, each on a project repository with two commits: `a slot starts as the project's main and follows it`; `an edit made in a slot lands on main, and the project's working files follow when it stands on main`; `it lands while the project's checkout is on another branch, and that checkout is not touched`; `main moved: the edit is put on top of it, checked again, and lands` (`again` called once); `two edits to the same lines: the second is told which files` (and main unchanged); `an edit with nothing in it lands nothing`; `export puts an unfinished branch into the project's repository`; `the third task waits for a slot` (perProject 2); `an idle slot's container is stopped after 15 minutes`.
