# sz:dive 평가용 프로필

`sz:dive`를 일반적인 '그릴링' 인터뷰 스킬과 견주기 위한 재료다. 한 번의 실행에서 시험받는 스킬은 대역(사람을 연기하는 LLM 에이전트)과 여러 차례 대화하고, 마지막에 한 쪽짜리 `idea.md`를 낸다. 채점자는 그 `idea.md`에 프로필의 숨은 사실이 몇 개나 맞게 들어갔는지 센다.

## 누가 썼고 누가 못 봤나

- 이 폴더의 프로필과 보고서는 스킬 작성자와 다른 에이전트가 썼다.
- `*/profile.md`는 봉인돼 있다. 대역과 채점자에게만 준다. 스킬이 프로필에 맞춰지지 않도록, 스킬 작성자는 실행이 끝날 때까지 이 파일들을 보지 않는다.
- `seed.txt`와 `workdir/`는 봉인 대상이 아니다. 실행 때 시험받는 스킬이 보게 되는 것들이다.

## 폴더

| 경로 | 무엇 |
| --- | --- |
| `<id>/seed.txt` | 그 사람의 첫 메시지. 실행의 첫 입력 |
| `<id>/profile.md` | 봉인. 누구인지, 말하는 방식, 숨은 사실 F1…(줄 종류, 드러나는 질문, 채점 기준), 끝났다고 느끼는 조건 |
| `<id>/workdir/` | 세션이 시작되는 폴더에 놓을 파일 |
| `report-source/report.html` | 보고서 원본. `report.pdf`는 이것을 헤드리스 Chrome으로 인쇄한 것 |

| id | 사용 사례 | workdir |
| --- | --- | --- |
| `app-other` | 앱 아이디어 발굴, 남의 앱(당근) | 비어 있음(`.gitkeep`) |
| `app-own` | 앱 아이디어 발굴, 자기가 출시한 앱(랠리판, 가상의 앱) | `README.md` (그 앱 저장소의 README) |
| `game-a` | 게임 아이디어 발굴, 보고서를 읽은 사람 | `report.pdf` |
| `game-b` | 게임 아이디어 발굴, 같은 보고서를 읽은 다른 사람 | `report.pdf` (game-a와 같은 파일) |

## 보고서

`report.pdf` "성공하는 인디게임의 6가지 공통점"(A4 5쪽, 쪽 번호 있음)은 이 평가를 위해 지어낸 가상의 보고서다. 기관, 연구진, 수치, 설문은 모두 만들어 낸 것이며, 첫 쪽에 그렇게 적혀 있다. 언급된 실제 게임에 대한 판정과 수치도 실제와 무관하다.

## 채점

각 `profile.md`의 3절에서 F마다 "채점" 줄이 그 사실이 맞게 들어갔다고 볼 핵심을 적는다. `idea.md`에 그 핵심이 있으면 맞음, 없으면 빠짐, 반대로 적혀 있으면 틀림. "반대" 표시가 붙은 사실은 뻔한 짐작과 어긋나는 것이라, 묻지 않고 짐작한 요약은 그 줄에서 틀린다.
