# 랠리판 개선 계획 한 장 요약 (2026-11-24 합의)

**문제**: 11/18에 23명이 왔고 코트는 4면이었습니다. `같은 급수끼리` 때문에 D급 신입 2명이 40분 동안 한 경기도 못 쳤고, 그중 1명은 클럽을 나갔습니다. 체육관이 지하라 인터넷이 안 돼서 Firestore, QR 출석, 알림도 멈춥니다.

**방향**: 급수로 나누지 않고 섞어 칩니다. 오래 기다린 사람이 먼저 칩니다. 인터넷 없이 운영진 폰 한 대로 돌립니다.

| **v1.5** | 대기 시간 표시, 인원 초과 경고 |

**v1.4 내용**
- **대진**: 가장 오래 기다린 4명을 그대로 뽑습니다. 팀은 급수 점수 합이 비슷하게 나누고, 그다음 같은 날 같은 파트너를 피합니다.
- **삭제**: `랜덤` 모드와 `같은 급수끼리` 옵션. 다른 두 클럽에는 미리 공지합니다.
- **출석**: 운영진이 이름을 누르면 대기 줄 맨 뒤로 들어갑니다. 신입은 현장에서 이름과 급수만 입력하고, 30일 안에 가입하지 않으면 익명 처리합니다.
- **휴식/대기 버튼**: 운영진만 쓸 수 있습니다. 대기로 돌아오면 줄 맨 뒤로 갑니다.
- **저장**: 대진 상태는 폰 안에 저장하고, 경기 점수는 인터넷이 되면 올립니다. "모임 시작" 버튼만 있습니다.
- **포기하는 것**: 지하에서 회원 폰으로 가는 실시간 현황판과 알림.

**완료 기준** (23명, 코트 4면, 경기 15분 조건으로 시뮬레이션 테스트)
- 2판 연속으로 쉬는 사람이 없어야 합니다.
- 모두 1시간에 2경기 이상 칩니다.
- 출석 인원이 24명 이하(코트 수×4 + 8)일 때만 지킬 수 있는 기준입니다.

**코드를 받으면 정할 것**
1. 지하에서 Firestore가 멈춘 원인 → 데이터를 저장할 방식
2. 경기 기록이 회원을 어떻게 참조하는지 → 익명 처리 방법

자세한 내용은 작업 폴더의 `PLAN-v1.4.md`에 있습니다.
