## 실제로 돌려서야 나온 것

1. **시간대.** 샌드박스는 UTC다. credeal의 테스트 하나가 "오늘 09:00"을 기대하고 00:00을 받았다. 들여온 제품의 샌드박스는 이제 이 Mac의 시간대를 받는다(`TZ`). 스튜디오가 지은 제품은 그대로다.
2. **집의 규칙으로 남의 제품을 쟀다.** 맞추기의 걷기가 화면 7장에서 결함 68건을 화면 기준에 적었는데, 대부분 "테마의 서체가 아니다", "글자 크기가 눈금 밖이다", "간격이 4px 격자 밖이다", "탭 바가 없다" 같은 집의 약속이었다. 들여온 제품의 걷기는 이제 어느 제품에나 참인 측정만 남긴다(`UNIVERSAL_RULES`: 대비, 터치 영역, 잘림, 가로 넘침, 겹침, 꺾인 라벨, 서체 미로딩, 빈 화면). 대비는 AA를 넘으면 결함이 아니다. credeal에 이미 적힌 기준에는 집의 규칙이 섞여 있다: 해가 되지 않고(그 규칙은 더 재지 않는다), 다음 전체 점검이 새로 쓴다.
3. **맞추지 않은 제품에 작업을 받았다.** 계획이 없는 제품은 개발 서버가 뜨지 않아 어떤 작업도 검사할 수 없다. 이제 main(또는 시작할 브랜치)에 계획이 없으면 맞추기 말고는 받지 않는다. "계획이 있다"는 것은 main의 내용으로 읽는다.
4. **맞추기의 값.** 191만 토큰, 27분. 한 번 치르는 값이지만, IDE의 에이전트가 폴더를 여는 것으로 하는 일을 스튜디오는 이만큼 들여야 시작한다.

같은 날 따로 나온 것: 소유자의 다른 작업(Codex, 만들기)이 한 라운드 60분 제한에 걸려 스튜디오에 의해 종료됐고, 오류에는 stderr의 Notion 로그인 경고가 원인처럼 찍혔다. 소유자의 말("시간제한은 제거합니다")대로 작업의 라운드에는 이제 시계를 두지 않는다. 그 경고는 이유가 아니라 알림이 됐다(작업 기록과 폰, 12시간에 한 번).

## 확인하지 않은 것

- 맞춘 브랜치를 합친 뒤의 빠른 수정과 전체 점검(합치는 것은 소유자의 일이라 하지 않았다).
- credeal의 프리뷰를 이 Mac의 브라우저로 본 것.
- 데스크톱의 들여오기 폼과 저장소 탭(따로 만들고 있다).
- main이 아닌 기준 브랜치, `apps/` 아래의 제품, Next와 Vite 저장소의 들여오기(테스트로만).
