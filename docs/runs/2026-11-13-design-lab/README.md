# 디자인 랩: 핸드북의 전과 후 (2026-11-13)

같은 브리프의 같은 방향을 두 소스 트리가 각각 그리게 하고, 그린 화면을 재고, 어느 쪽인지 모르는 리뷰어에게 보였다. 무엇을 왜 했는지는 `docs/superpowers/specs/2026-11-13-platform-design-handbooks-design.md` §5, 도구는 `packages/daemon/scripts/design-lab/`에 있다.

| | 전 | 후 |
|---|---|---|
| 소스 트리 | `962af1f` (어제까지의 지침과 측정) | 브랜치 `design-handbook` (핸드북, 서체 셋, 둘째 색, 새 측정) |
| 그린 것 | 방향 9개 × 1장, 그리고 같은 날 실제 엔진이 그린 결투 3장 | 방향 9개 × 1장, 결투 방향 3개는 한 장씩 더 |
| 그린 쪽 | 방향마다 에이전트 하나, Opus, 추론 강도 high, 그 트리의 `check_mockup`을 루프백 주소로 | 같음 |

브리프는 넷이다: `duel`(오늘의 실제 프로젝트, 모바일), `dues`(모바일, 목록과 입력), `quote`(웹 페이지), `orders`(웹 앱). 뒤의 셋은 주 엔진 노릇을 한 에이전트가 썼고, 스튜디오의 검사에 걸린 곳(진입 경로의 모양, 범위 밖의 테마, 600자를 넘는 조작 설명)은 뜻을 지키며 고쳤다.

## 결과

- 리뷰어가 어겼다고 본 규칙: 화면당 4.3건 → 1.9건.
- 둘 중 하나를 고르게 했을 때: 36표 가운데 25표가 후. 실제 엔진의 화면과 붙인 세 쌍은 9표 전부 후.
- 눈가림 절대 점수(일곱 축 평균, 리뷰어 3명): 7.03 → 7.02. 움직이지 않았다.
- 12px 이하로 놓인 글자(모바일 중앙값): 50% → 13%. 두 서체를 쓴 화면: 12장 중 8장 → 0장. 밝은 화면의 검정 띠: 3장 → 0장.
- 옛 감사는 옛 지침의 화면 전부에 메이저 0건이라고 답했다. 새 감사는 같은 12장에 평균 2.9건을 적는다.
- 리뷰어가 화면마다 꼽은 가장 나쁜 한 가지는 24장 중 13장(전 6, 후 7)에서 깨진 렌더링이었다: 겹쳐 그려진 상태, 갈라진 숫자, 도크에 잘린 내용, 가장자리를 넘은 것. 핸드북이 다루지 않은 것이고, 다음에 재야 할 것이다.

판정(남긴 것, 고쳐서 다시 볼 것, 버린 것)은 `notes.json`에 있다.

## 파일

| 파일 | 내용 |
|---|---|
| `notes.json` | 판정과 그 근거, 검증하지 못한 것 |
| `metrics/<군>-<브리프>-<방향>.json` | 화면마다 잰 값. 군: `baseline`, `production`(실제 엔진), `draft`(후의 첫 초안, 측정을 받기 전), `treatment`, `treatment2` |
| `checks.json` | 새 검사마다: 옛 지침의 12장 중 몇 장, 새 지침의 첫 초안과 최종 중 몇 장을 잡았는가 |
| `review-results.json`, `review-key.json` | 눈가림 리뷰의 답 전부(점수 3명, 규칙 판독 2명, 쌍 비교 3명)와, 번호가 어느 군의 어느 화면이었는지 |
| `review-prompts/` | 리뷰어가 받은 지침 그대로 |
| `briefs/` | 브리프마다 템플릿, 화면 명세, 방향표 |

그린 페이지와 캡처는 여기에 없다(작업 폴더 `.design-lab/`에 있고 저장소에 넣지 않는다).

## 읽을 때 조심할 것

- 방향 하나에 한두 장이다. 같은 지침에서도 표본 사이의 차이(약 0.4점)가 전후의 차이보다 크다.
- 리뷰어는 어느 쪽인지 몰랐지만 그린 쪽과 같은 벤더의 모델이다. 실제 감사의 리뷰어로는 돌리지 않았다.
- 재고 본 것은 시안이다. 빌드에서 어떻게 되는지, 그림 규칙이 어떻게 작동하는지는 이 랩으로 알 수 없다.
