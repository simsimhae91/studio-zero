# 살아 있는 제품: 만든 날의 실제 실행 (2026-11-15)

설계는 `docs/superpowers/specs/2026-11-15-living-product-design.md`. 여기는 소유자의 Mac에서 실제로 돌린 것과 거기서 나온 것만 적는다. 대상은 임시 폴더의 제품 하나: "모임 정산"(엔빵). Node 내장 기능만 쓰는 서버와 SQLite, 폰 화면 하나.

## 1. L 레인이 처음으로 끝까지 갔다

`/sz:build`를 두 번 돌렸다. 사람은 끼어들지 않았다.

| | 시간 | 출력 토큰 | 에이전트 | 끝 |
|---|---|---|---|---|
| 1차 | 30분 | 13.5만 | 2 | M1을 만들고 멈춤 |
| 2차 (같은 폴더에서 이어서) | 1시간 38분 | 29만 | 12 | M1·M2·M3 닫힘 |

1차가 멈춘 까닭: 만드는 쪽이 코드보다 먼저 쓴 검사(`flows/m1-create-and-split.sh`)에 따옴표 버그가 있었다. 얼렸기 때문에 스스로 못 고쳤고, 다른 누구도 고칠 길이 없었다. 정직하게 "막혔다"고 보고했고, 실행 전체가 거기서 끝났다. 그래서 중재자(`sz:arbiter`: 만들지도 판정하지도 않는 쪽이 검사가 틀렸는지 제품이 틀렸는지 정하고, 검사는 "어떻게 검사하는지"만 고친다)와 "파일에서 이어 하기"를 만들었다.

2차: 계획 단계가 파일을 읽고 M1을 "만들어졌고 검증 전"으로 돌려줬다. 중재자가 검사를 고치고 계약에 적었다. 그 뒤 마일스톤마다 구현 → 검증 → 닫기.

- 주장 21개 가운데 증명 19, 반증 0, 주인 몫 2("토스처럼 느껴지는가", "이 제품만의 화면으로 읽히는가").
- M2 검증자가 결함 하나를 잡았다: 최근 모임이 5개 이상이면 홈의 '만들기'를 누를 수 없다. 고친 뒤 다시 봐서 통과.
- 검증자가 계약 밖에서 본 것 15건(나머지가 생기는 모임에서 '1인당' 금액이 실제 송금과 1원 다름, 입력 칸이 서버 한도보다 김, 긴 이름의 줄바꿈 등).
- 결과물: 3,838줄(서버, 최소 송금 계산, 화면, 검사 26개, 흐름 10개). 명세는 "반드시 잘해야 하는 한 가지"(정산이 1원도 안 틀리고 송금 횟수가 실제 최소)를 먼저 정하고 기능을 깊이 순서로 쌓았다.

세션이 한 가지를 스스로 걸렀다: 실행 초반에 "완료" 모양의 알림이 하나 들어왔는데, 디스크(커밋, 계약의 판정, 증거 파일)와 맞지 않는다는 이유로 결과로 보고하지 않고 실제 완료를 기다렸다. 그 알림이 어디서 왔는지는 확인하지 못했다.

## 2. 훅이 실제 세션에서 걸리는 것을 봤다

앞선 기록의 "확인하지 않은 것"이었다. 2차 실행의 기록에는 거절이 한 번도 없었다(걸릴 일이 없었던 것인지 구분이 안 됐다). 작은 세션으로 직접 봤다.

- 얼린 검사를 편집 도구로 고치라고 시켰다: 거절됐고, 파일은 그대로였다.
- 그 세션이 멈출 때: "증명 안 된 주장이 하나 남아 있고, 이 작업은 끝나지 않았습니다"라고 스스로 말했다(멈춤 훅).
- 계약을 닫은 뒤 "제품을 3만원으로 바꾸고 검사도 맞춰 고쳐라": 제품은 바꿨고, 검사 편집은 거절됐다. 세션은 선택지 셋(제품을 되돌린다 / 약속을 바꾸는 것이면 새 계약에 적는다 / 검사 방식이 틀린 것이면 중재자)을 내놓았고, "값 변경이라 중재자의 일이 아닌 것 같다"고 판단했다.
- 중재자는 같은 훅을 통과해 얼린 파일을 고쳤다(2차 실행의 중재자 기록에서 확인).

## 3. 독립 검토가 구멍 열을 찾았다

새 코드를 Opus 에이전트 하나가 내 의견 없이 읽고 돌려 봤다(15분, 20만 토큰). 실제 결함 10건, 그중 넷은 "깨뜨린 약속 위로 닫을 수 있는 길"이었다.

- 닫힌 계약을 다시 닫으면 깨졌다는 기록이 "참"으로 덮였다.
- 닫힌 계약의 판정을 고쳐 약속을 목록에서 뺄 수 있었다.
- 폴더 하나를 얼린 계약이 닫히면, 나중 작업이 그 폴더에 파일을 더하는 것까지 막혔다.
- 장부 파일이 깨지면(두 브랜치의 병합 충돌) 안전장치가 조용히 꺼졌다.
- 가리키고 말하는 창: 가리키는 중의 두 번째 누름이 제품에 닿았고, 적는 글자가 제품의 단축키로 새어 나갔고, 페이지가 막대를 지우면 돌아오지 않았다.
- 워크플로: 두 번째 검증이 빠뜨린 주장이 "반증"에서 사라져 닫히지 않은 계약 위에 다음 마일스톤을 지었다.

전부 고치고 각각 테스트나 모의 실행을 붙였다. 2차 실행의 검증자도 같은 날 하나를 짚었다: "얼린 파일의 해시가 없어 얼린 뒤 바뀌지 않았는지 확인할 수 없다." 얼릴 때 지문을 찍고, 훅 뒤로(셸로) 바뀐 검사는 중재자가 보기 전까지 그 작업의 빚으로 남게 했다.

## 4. 돌봄: "이 서비스 좀 돌봐 줘"

소유자의 말투 한 줄을 줬다. 스킬 이름은 대지 않았다. 11분 30초, 출력 2.3만 토큰.

- 약속 19개를 전부 다시 보였다: 검사 26개, 흐름 10개(303초), 폰 화면 6장. 장부에 19건이 "참"으로, 각각 무엇을 돌렸는지와 파일 지문과 함께 적혔다.
- 처음 온 사람처럼 눌러 봤다: 링크로 온 사람은 세 번 누르면 지출이 들어간다. 132,000원 ÷ 3 = 44,000원.
- 남은 일 17줄 가운데 이미 해결된 6줄을 닫고, 줄마다 어느 커밋에서 해결됐는지 적었다. 표본으로 대조했다: 입력 칸 길이 20/10/20은 코드와 서버 한도가 실제로 같다.
- 남은 것 다섯을 근거·크기와 함께 순위 매겼다: '1인당' 1원 불일치, 히어로 문장의 줄바꿈, 실패를 적는 곳이 없음, 백업이 없음, 흐름 검사가 5분.
- 하나를 권했다('1인당'): "정산 결과가 맞다는 이 서비스가 반드시 잘해야 하는 한 가지"라는 이유로. 그리고 그것이 명세의 결정을 바꾸는 일이라 소유자가 정해야 한다고 말했다.
- 보지 못한 것을 말했다: 배포 전이라 실제 사용자, 실제 폰의 Safari.
- 소유자의 8770 포트와 `data/`는 건드리지 않았고, 서버와 작업 폴더를 남기지 않았다.

## 5. 피드백 한 라운드

소유자 대신 내가 네 가지를 말했다(작은 수정, 사실과 다를 수 있는 말, 취향, 약속과 저장 모양을 바꾸는 요청). 37분 45초, 출력 10만 토큰, 커밋 5개(하나씩 되돌릴 수 있게).

| 한 말 | 한 일 |
|---|---|
| "1인당 금액 1원 안 맞는 거 고쳐 줘. 어떻게 보일지는 네 의견대로." | 의견을 내고 정했다: 한 숫자로 정확히 말할 수 없으면 그 숫자를 빼고, 이름을 고른 사람에게는 '내 몫 33,333원'을 보인다. 범위 표기는 검토하고 버린 이유를 적었다 |
| "'누구세요?' 카드, 이름 고른 뒤에도 계속 떠 있으면 거슬릴 것 같아." | 먼저 화면을 봤다. 이미 고르면 사라진다. 아무것도 고치지 않고 전후 사진만 남겼다 |
| "'보냈어요' 버튼 주황색이 좀 튀는 느낌." | 회색으로. "줄 안의 버튼은 그 줄의 금액보다 조용해야 한다." 보낸 뒤의 초록은 상태 표시라 그대로 |
| "지출마다 같이 쓴 사람을 고를 수 있으면 좋겠어." | 계약 `m4-shared`(주장 6개, 그중 하나는 "이 변경 전 모양의 DB를 열어도 지출이 그대로 있다") → 구현 → 검증자 |

네 번째에서 검증자는 6개를 증명하고, **앞선 19개 약속을 전부 다시 보였고**(장부에 25건 모두 이 작업 중에 "참"), 결함 넷을 찾았다. 큰 것: 지출 시트를 열어 둔 사이 새 사람이 들어오면 그 사람 몫이 0원이 된다. 고쳤다. 기본값을 "모두"로 둬서 옛 약속은 하나도 바꾸지 않았다.

배운 것 다섯 줄이 `.sz/owner.md`에 소유자의 말 인용과 함께 적혔다("줄 안의 단추는 그 줄의 금액보다 조용하다", "한 번 답한 물음은 화면에 남지 않는다" 등). 끝에는 "더 있나요"가 아니라 다음에 자기가 할 것 하나를 말했다(히어로 문장의 줄바꿈).

여기서 나온 흠 둘을 고쳤다.

- 피드백 페이지가 한 항목의 사진 여덟 장을 구분 없이 늘어놓았고 처음 두 장이 둘 다 "전"이었다. 같은 이름의 전·후를 짝지어 나란히 놓고, 멈춘 화면을 먼저, 나머지는 몇 장인지만 적게 했다.
- 스킬은 "저장 모양이 바뀌면 소유자의 예를 기다린다"였는데 세션은 기다리지 않았다(앉아 있는 사람이 없는 실행이었다). 규칙이 넓었다: 있는 것을 그대로 옮기고 그것을 주장으로 증명하는 변경은 기다릴 까닭이 없다. 잃을 수 있을 때만 기다리게 고쳤다.

## 6. 가리키고 말하는 창

`sz-eyes web review`를 헤드리스 Chrome으로 테스트에서 돌리고(가리키는 중의 누름이 제품에 닿지 않는지, 적는 글자가 새지 않는지, 막대가 지워져도 돌아오는지), 실제 창으로 한 번 띄웠다(393×659, 몇 초). 소유자가 직접 써 본 적은 아직 없다.

## 7. 넓히기: 끝난 제품에 운영 준비를 더했다

닫힌 계약 넷과 서 있는 약속 25개가 있는 제품에 `/sz:build`를 다시 돌렸다. 요청은 내가 주인 대신 썼다: 오류를 남기는 파일, 주인만 보는 화면의 수, 백업과 되살리기, 히어로 문장의 줄바꿈, 5분 걸리는 흐름 검사를 빠르게. 사람은 끼어들지 않았다.

| 시간 | 토큰(전체) | 에이전트 | 도구 호출 | 끝 |
|---|---|---|---|---|
| 1시간 48분 | 98.7만 | 9 | 334 | M5·M6 닫힘 |

- 계획 단계는 명세를 새로 쓰지 않고 늘렸다. 이미 틀려 있던 줄(M4와 피드백으로 바뀐 것)을 고쳐 표시했고, 옛 약속을 대체하는 것은 하나도 없다고 정했고, 빠른 검사를 먼저 지었다(M6을 검증하려면 흐름을 여러 번 돌려야 하므로).
- **M5 `m5-tidy`**: 증명 6. 흐름 전체가 341초에서 80초로(세 번 연달아 79·80·80초, 얼린 `all.sh`는 그대로 두고 새 실행기를 옆에 지음). 히어로 문장은 393px에서 띄어쓰기에서만 꺾인다. 앞선 약속 25개를 다시 보였고 깨진 것 없음.
- **M6 `m6-care`**: 증명 6, 주인 몫 1. `errors.log`(1MB에서 넘김), `/admin/<ADMIN_KEY>`(키가 16자 미만이면 꺼짐, 틀린 키에는 없는 모임과 같은 404), `npm run backup`·`npm run restore`. 새 표 없이 있는 표에서 세므로 이 변경 전에 만든 모임도 센다. 앞선 약속 31개를 다시 보였고 깨진 것 없음.
- **검증자가 데이터를 잃는 결함을 잡았다.** 같은 DB로 서버 둘을 띄우고 나중 것을 끄면 표시 파일이 사라져, 되살리기가 떠 있는 서버 밑의 DB를 갈아 끼웠고 그 뒤에 적은 지출이 사라졌다. 처음 검증에서 `backup-restore`가 반증됐고, 고친 뒤(서버마다 제 표시, DB 잠금 확인) 두 번째 검증에서 증명됐다.
- 지금 제품: 서 있는 약속 37개, 5,838줄. 주인이 볼 것 셋이 남은 일에 있다("토스처럼 느껴지는가", "이 제품만의 화면으로 읽히는가", "나만 보는 화면이 한눈에 읽히고 백업이 손으로 할 만한가").
- 세션의 보고를 디스크(계약, 장부, 증거, 커밋)와 대조했다: 맞았다. 세션은 틀린 곳 둘을 스스로 짚었다(닫는 커밋의 "앞선 약속 31개"는 25개가 맞음, 워크플로 결과의 "눈에 띈 것"에 고치기 전 문장이 남음).

## 사고: 다른 프로젝트의 서버를 껐다

M5를 짓던 에이전트가 사진을 찍으려고 포트 번호를 직접 골랐다(8817). 그 포트에는 주인의 다른 프로젝트(`~/orca/projects/claude-multi-agent-plugin`의 `.war-room-state/scratch/claude/s2/archive/07/dist`, 화면 제목 '하루밖')를 보여 주는 서버가 떠 있었다. 에이전트의 서버는 뜨지 못했고, 에이전트는 그 포트에서 답하는 것을 제 것으로 알고 사진을 찍은 뒤, `lsof -ti tcp:8817 | xargs kill`로 껐다(2026-11-15 19:03 KST). 그 서버가 어떻게 띄워졌는지는 찾지 못해 되살리지 못했다. 잘못 찍은 사진은 증거에 남지 않았다(바로 다시 찍었다).

원인은 하네스에 있었다. 워크플로가 "지도에 없는 포트를 쓰라"고 했고(번호를 고르게 됨), 포트로 찾아 끄는 것을 막는 것이 없었다. 고친 것:

- `hooks/guard-others.mjs`: 이 작업이 띄우지 않은 것을 끄는 명령을 거절한다. 포트를 잡고 있는 것(`lsof | xargs kill`, `kill $(lsof -t ...)`, `fuser -k`, `kill-port`), 이름에 맞는 전부(`pkill`, `killall`), 모든 컨테이너(`docker stop $(docker ps -q)`, `prune`), 모든 시뮬레이터(`simctl shutdown all`). 커밋 메시지나 파일에 쓰는 글에 그 낱말이 있는 것은 명령으로 읽지 않는다.
- `sz-eyes port`: 기계가 주는 빈 포트. 워크플로·스킬·검증자가 "포트는 여기서 받고, 띄운 프로세스 번호를 쥐고 있다가 그 번호로만 끈다. 답하는 것이 제 것인지 보고 나서 본다"를 따른다.
- 실제 세션에서 봤다: 내가 띄운 더미 서버의 포트를 주고 "이 명령으로 비워 달라"고 시켰다. 거절됐고, 세션은 우회하지 않고 주인이 직접 돌릴 명령을 보여 줬고, 더미는 살아 있었다.

같은 실행에서 나온 작은 것 셋도 고쳤다.

- 남은 일 목록이 이미 끝난 줄을 계속 열어 두었다(실패 기록, 백업, '1인당' 표기). `sz-eyes backlog done "<줄의 낱말>" --by "<끝낸 계약이나 커밋>"`을 만들고, 닫는 단계·피드백·돌봄이 쓰게 했다.
- 워크플로가 두 번째 검증에 첫 검증이 본 것을 넘기고, 아직 그런 것만 돌려받는다.
- 닫는 단계가 수를 다시 세지 않고 검증자가 돌려준 수를 쓴다.

워크플로 스크립트의 논리(무엇을 다음 에이전트에게 넘기고, 언제 멈추는지)를 모델 없이 돌려 보는 테스트(`packages/eyes/test/build-workflow.test.ts`)를 붙였다.

## 내 실수

임시 작업 폴더에 의존성 폴더를 링크로 걸어 쓰다가 그 링크 하나(`packages/eyes/node_modules`)를 커밋에 넣었고, 본 브랜치에 합치자 실제 폴더가 자기 자신을 가리키는 링크로 바뀌었다. 지워진 것은 pnpm이 만드는 링크뿐이어서 `pnpm install --offline --frozen-lockfile`로 되살렸고, 그 커밋에서 링크를 뺐고, `.gitignore`가 링크도 무시하게 했다.

## 확인하지 않은 것

- 소유자 본인이 피드백 고리와 가리키는 창을 써 본 것. 이 기록의 피드백은 내가 대신 말한 것이다.
- 취향의 갈림을 둘 다 만들어 나란히 보여 주는 길(이번 라운드에는 그런 항목이 없었다).
- 게시한 페이지의 댓글로 피드백을 받는 길.
- 약속을 실제로 바꾸는 변경(`--supersedes`)과 중재자의 "나중 요청이 대신함" 판정: 테스트와 작은 세션으로만 봤다. 넓히기 실행은 옛 약속을 하나도 바꾸지 않는 길을 골랐다.
- 새 훅(`guard-others`)과 `sz-eyes port`가 긴 실행 전체에서 어떻게 작동하는지. 작은 세션 하나와 테스트로만 봤다.
- 배포된 서비스의 오류·사용 수치. iOS에서 가리키고 말하기.
