카카오·Google 로그인 붙이기: 공용 개발자 앱 등록

한 줄 요약

카카오와 Google에 개발자 앱을 하나씩 만들고, 리다이렉트 주소 하나를 등록하고, 키 네 개를 Studio Zero의 금고에 넣습니다. 그 뒤로 이 Mac에서 짓는 모든 프로토타입이 그 앱으로 로그인합니다.

Studio Zero는 Mac에서 웹과 모바일 프로토타입을 짓는 도구입니다. 짓는 제품마다 자기 백엔드(Supabase)를 하나씩 받고, 로그인은 이메일과 비밀번호로 바로 됩니다. 카카오와 Google 로그인은 개발자 앱의 키가 있어야 하고, 그 키는 본인만 만들 수 있습니다. 이 글은 그 절차입니다. 키가 없어도 스튜디오는 돕니다. 그때는 제품에 이메일 로그인만 나옵니다.

먼저 알아 둘 것

앱은 제공자마다 하나면 됩니다. 프로토타입마다 앱을 만들지 않습니다. 스튜디오용 앱 하나를 모든 프로토타입이 같이 씁니다. 제품을 실제로 내보낼 때는 그 제품의 앱을 따로 만듭니다(출하할 때).

등록할 주소도 하나입니다.

http://localhost:49200/oauth/callback

이 주소는 Studio Zero 데몬의 것입니다. 프로젝트마다 백엔드의 포트가 다르고, 제공자는 등록된 주소와 글자 하나까지 같은 곳으로만 사람을 돌려보냅니다(카카오는 열 개까지만 등록됩니다). 그래서 프로젝트의 주소가 아니라 데몬의 주소 하나를 등록하고, 데몬이 돌아온 사람을 그 로그인을 시작한 프로젝트로 넘겨 줍니다.

주소는 그대로 붙여 넣습니다. http(https 아님), localhost(127.0.0.1 아님), 끝에 슬래시 없음. 하나라도 다르면 제공자가 로그인을 거절합니다.

필요한 것. 카카오 계정(본인인증을 마친 것), Google 계정, Studio Zero가 떠 있는 Mac.

카카오

콘솔은 developers.kakao.com/console/app입니다. 메뉴 이름은 2025년 12월 3일 개편 뒤의 것입니다. 그 전에 쓰인 글은 리다이렉트 URI를 [카카오 로그인] > [일반]에서 찾으라고 하는데, 지금은 앱 키 아래로 옮겨졌습니다.

  1. 앱을 만듭니다. 앱 목록에서 [앱 생성]. 앱 이름(예: Studio Zero), 회사명(개인이면 본인이나 서비스 이름), 카테고리를 넣고 저장합니다. 앱 아이콘도 올려 둡니다. 다음 단계에 필요합니다.
  2. 비즈 앱으로 전환합니다. [앱] > [일반] > [비즈니스 정보] > [개인 개발자 비즈 앱]. 사업자등록이 없어도 됩니다. 앱 소유자가 본인인증을 마쳤어야 하고(오른쪽 위 프로필의 [계정 설정] > [본인인증]), 앱에 아이콘이 있어야 합니다. 사업자가 있으면 같은 자리의 [사업자 정보 등록]을 씁니다.
  3. 카카오 로그인을 켭니다. [카카오 로그인] > [사용 설정]에서 상태를 ON으로.
  4. 동의항목을 설정합니다. [카카오 로그인] > [동의항목]에서 닉네임(profile_nickname), 프로필 사진(profile_image), 카카오계정(이메일)(account_email) 셋을 켭니다.
  5. 리다이렉트 URI를 등록합니다. [앱] > [플랫폼 키] > [REST API 키]를 열고 리다이렉트 URI 칸에 위 주소를 넣습니다.
  6. 클라이언트 시크릿을 확인합니다. 같은 화면의 [클라이언트 시크릿]에서 코드를 발급하고 활성화가 ON인지 봅니다.

가져갈 값은 둘입니다: REST API 키(이것이 client id입니다)와 클라이언트 시크릿 코드. OpenID Connect는 켜지 않아도 됩니다.

2번을 건너뛰면 로그인이 안 됩니다. Supabase는 카카오에 닉네임, 프로필 사진, 이메일 세 항목을 기본으로 요청합니다. 이메일 동의항목은 비즈 앱에서만 설정할 수 있고, 설정되지 않은 항목을 요청하면 카카오가 KOE205로 거절합니다.

Google

콘솔은 console.cloud.google.com입니다. 예전의 "OAuth 동의 화면"은 지금 Google Auth Platform이라는 이름 아래에 Branding, Audience, Clients, Data Access로 나뉘어 있습니다.

  1. 프로젝트를 만들거나 고릅니다.
  2. Google Auth Platform을 시작합니다. Overview의 Get started에서 앱 이름과 지원 이메일을 넣고, Audience는 External을 고르고, 연락처를 넣습니다.
  3. 테스트 사용자를 넣습니다. 게시 상태가 Testing인 동안은 Audience의 Test users에 넣은 Google 계정만 로그인됩니다(100명까지). 프로토타입에 로그인해 볼 계정을 넣습니다.
  4. 클라이언트를 만듭니다. Clients에서 Create client, 유형은 Web application. Authorized redirect URIs에 위 주소를 넣습니다. Google은 https만 받지만 localhost 주소는 예외입니다. Authorized JavaScript origins는 비워 둡니다.
  5. Client ID와 Client secret을 그 자리에서 복사합니다. 시크릿 전체는 만들 때 한 번만 보입니다. 그 뒤에는 끝 네 글자만 나오므로, 놓쳤으면 새로 만들어야 합니다.

범위는 기본(openid, email, profile)이면 됩니다. 설정이 반영되는 데 5분에서 몇 시간이 걸릴 수 있습니다.

키를 금고에 넣기

Studio Zero 저장소 폴더에서, 값을 하나 복사할 때마다 그 값의 줄을 실행합니다. 값은 클립보드에서 바로 금고(macOS 키체인)로 들어갑니다.

pbpaste | pnpm -s sz vault set login/kakao/client-id
pbpaste | pnpm -s sz vault set login/kakao/client-secret
pbpaste | pnpm -s sz vault set login/google/client-id
pbpaste | pnpm -s sz vault set login/google/client-secret

pnpm -s sz vault list로 네 이름이 있는지 봅니다. 값은 나오지 않고 이름과 넣은 시각만 나옵니다.

키를 채팅, 문서, 저장소에 붙이지 않습니다. 금고에 들어간 시크릿은 프로젝트의 인증 서비스에만 전달되고, 엔진이 코드를 쓰는 샌드박스에는 들어가지 않습니다.

확인

  1. 프로젝트에서 작업을 하나 돌리거나 프리뷰를 엽니다. 그때 그 프로젝트의 백엔드에 두 제공자가 켜집니다. 데몬을 다시 띄울 필요는 없습니다.
  2. 제품의 로그인 화면에서 카카오 단추와 Google 단추를 한 번씩 눌러 끝까지 로그인합니다.

이 확인은 처음 한 번이면 됩니다. 그 뒤로는 스튜디오가 빌드마다 두 단추를 직접 눌러서, 제품이 올바른 제공자로 올바른 주소를 들려 보내는지를 봅니다. 제공자의 로그인 화면부터는 사람의 몫이라 스튜디오는 그 문 앞에서 멈춥니다.

안 될 때

화면에 뜨는 것원인과 조치
카카오 KOE006리다이렉트 URI가 등록된 것과 다릅니다. REST API 키의 리다이렉트 URI를 위 주소와 글자 단위로 맞춥니다.
카카오 KOE205요청한 동의항목이 설정돼 있지 않습니다. 대개 이메일입니다. 비즈 앱 전환과 동의항목을 확인합니다.
카카오 KOE004카카오 로그인이 꺼져 있습니다. 사용 설정을 ON으로.
Google redirect_uri_mismatchAuthorized redirect URIs가 위 주소와 다르거나, 방금 고친 것이 아직 반영되지 않았습니다.
Google "액세스 차단됨"(access_denied)앱이 Testing 상태인데 그 계정이 Test users에 없습니다.
localhost:49200에 연결할 수 없음Studio Zero 데몬이 꺼져 있습니다. pnpm -s sz status로 확인합니다.
localhost:49200에서 404데몬이 시작한 적 없는 로그인입니다(오래 둔 탭, 백엔드를 지운 프로젝트). 제품의 로그인 화면에서 다시 시작합니다.

이 앱으로 되는 것과 안 되는 것

  • 이 Mac의 브라우저에서 여는 프로토타입에 로그인하는 데 씁니다. 등록한 주소가 localhost이므로 다른 기기에서 연 프로토타입은 이 앱으로 로그인할 수 없습니다.
  • Google은 Testing 상태에서 테스트 사용자로 넣은 계정만 받습니다.
  • 동의 화면에는 이 앱의 이름이 뜹니다. 제품의 이름으로 띄우려면 제품의 앱이 필요합니다. 그것이 출하할 때의 일입니다.

확인한 범위와 출처

이 절차대로 등록한 앱으로, 2026년 11월 14일에 Studio Zero가 지은 제품에서 카카오와 Google 로그인이 끝까지 되는 것을 확인했습니다. 카카오 콘솔이 http://localhost 주소를 받는 것도 그때 확인했습니다. 메뉴 이름과 규칙은 아래 공식 문서를 따랐고, 콘솔이 바뀌면 달라질 수 있습니다.

  • 카카오: 앱 설정, 카카오 로그인 설정하기, 앱과 앱 키 개편 안내, KOE205와 이메일 동의항목(데브톡)
  • Google: Google Auth Platform, OAuth 클라이언트 만들기, Audience와 게시 상태
  • Supabase: Login with Kakao, Login with Google
